# Раздел документации

`tnt-docs` превращает каталоги файлов markdown в раздел документации
прямо на узле Tarantool: меню разделов, поиск по-русски в окне ⌘K,
светлая и тёмная тема, подсветка кода, план ненаписанных страниц —
внутри рамки сайта приложения.

```lua
local docs = require('tnt.docs')

docs.new({ directory = 'docs' }).attach(httpd)   -- httpd — сервер http.server
```

Раздел отвечает страницами сразу: разметка разбирается на узле, и правка
документа видна без сборки и без перезапуска.

## Зачем пакет

Документацию пишут markdown рядом с кодом, а читают браузером. Между
этими двумя концами — работа, которую каждый раздел документации делает
одинаково: разложить страницы по темам, дать по ним поиск, нарисовать
их на рамке сайта, не дать чужой разметке исполнить сценарий. Пакет
делает это одним вызовом:

- **Меню — от приложения.** Разделы меню и порядок страниц в них задаёт
  приложение — файлом меню, группами или тем и другим. Пакет рисует
  из них колонку-гармошку, «назад» и «вперёд» по порядку меню и главную
  с карточками страниц.
- **План виден читателю.** Пункт меню, за которым страницы ещё нет,
  открывается заглушкой «скоро» с тем, что на ней будет и чего для этого
  не хватает, а сводная страница показывает весь план одной таблицей.
- **Поиск по-русски.** Указатель строится по разделам страниц, и слово
  сводится к основе: запрос «шаблоны» находит и «шаблон», и «шаблонов».
  Окно ⌘K отвечает по мере набора, страница выдачи работает и без
  сценариев.
- **Разбор — один раз на правку.** Страницы и указатель собираются
  заново, только когда разметка на диске стала другой, и прогреваются
  в фоне при подъёме: посетитель не ждёт разбора всего каталога.
- **Рамка сайта — настройками.** Марка, пункты шапки, ссылки наружу
  и подвал приходят от приложения, и раздел стоит внутри сайта, а не
  рядом с ним.
- **Вид едет роком.** Стили, сценарии, значки и шрифты собраны заранее
  и упакованы в модуль: узел раздаёт их из памяти, и ни отдельного
  сервера статики, ни сети доставки разделу не нужно.
- **Безопасно по умолчанию.** Разметка экранирует всё, что пришло
  из документа, а каждый ответ несёт правило источников браузера
  без встроенных сценариев и стилей.

Зависимости:
[`tnt-markdown`](https://github.com/tnt-skein/tnt-markdown) — разбор
разметки,
[`tnt-router`](https://github.com/tnt-skein/tnt-router) — адреса,
метка версии и раздача файлов,
[`tnt-template`](https://github.com/tnt-skein/tnt-template) — рамка
и страницы,
[`tnt-morphology`](https://github.com/tnt-skein/tnt-morphology) — основа
слова для поиска,
[`tnt-fs`](https://github.com/tnt-skein/tnt-fs) — чтение каталогов,
[`tnt-log`](https://github.com/tnt-skein/tnt-log) — журнал,
[`tnt-clock`](https://github.com/tnt-skein/tnt-clock) — часы сверки,
[`tnt-context`](https://github.com/tnt-skein/tnt-context) — контекст
в файбере прогрева,
[`tnt-must`](https://github.com/tnt-skein/tnt-must) — проверка настроек,
[`tnt-external`](https://github.com/tnt-skein/tnt-external) — подмена
часов и уступки в проверках — и рок `http`, сервер роли. Ни `box`,
ни кластер разделу не нужны.

## Как пользоваться

### Заведение: `docs.new`

`docs.new(options)` отдаёт роутер
[`tnt-router`](https://github.com/tnt-skein/tnt-router): раздел
подключается к своему серверу (`attach`), к роутеру приложения (`mount`)
либо зовётся напрямую (`dispatch`).

```lua
local docs = require('tnt.docs')
local server = require('http.server')

local httpd = server.new('127.0.0.1', 8088, { log_requests = false, idle_timeout = 60 })

docs.new({
    directory = 'docs',
    title = 'Документация',
    groups = {
        { title = 'Начало', pages = { 'install', 'usage' } },
        { title = 'Справочник', pages = { 'api' } },
    },
    hidden = { 'drafts' },
}).attach(httpd)

httpd:start()
```

Подключение к серверу подменяет его обработчик целиком: раздел занимает
свой сервер и свой порт. Приложению со своим роутером — `mount`, ниже.

| Настройка | Умолчание | Что делает |
|---|---|---|
| `directory` | — | каталог разметки: страница `<имя>.md` — адрес `<начало>/<имя>` |
| `roots` | — | своды: `{ section, directory, hidden }`, адрес `<начало>/<свод>/<имя>` |
| `prefix` | `/docs` | начало адресов раздела |
| `title` | `Документация` | название раздела: главная, 404, заголовок вкладки |
| `start` | нет | куда ведёт начало раздела; нет — главная с карточками |
| `menu` | нет | файл меню: разделы, страницы, состояние по плану |
| `groups` | нет | группы по порядку — после разделов меню: `{ title, section, pages }` |
| `rest` | `Прочее` | группа для страниц, которых нет нигде |
| `hidden` | нет | документы каталога `directory`, которых на сайте нет |
| `plan` | нет | сводная страница плана `page` и план страниц `pages` |
| `suggestions` | нет | подсказки пустого окна поиска: `{ icon, title, note, href }` |
| `card` | нет | карточка пакета по имени страницы и своду — функция |
| `frame` | марка — `title` | рамка сайта: марка, пункты шапки, ссылки, подвал |
| `recheck` | `1` | сколько секунд разобранное не сверяется с диском |
| `warm` | `true` | прогревать ли раздел в фоне при подключении |
| `views` | шаблоны пакета | свой каталог шаблонов страниц |

Разметка — ровно одно: `directory` либо `roots`. Настройки проверяются
целиком при заведении: незнакомый ключ и негодное значение — ошибка
программиста, и бросок винит строку, которая завела раздел.

```lua
docs.new({ directory = 'docs', hiden = { 'drafts' } })
--> настройки раздела: ключа «hiden» нет, есть card, directory, frame, groups,
-->     hidden, menu, plan, prefix, recheck, rest, roots, start, suggestions,
-->     title, views, warm
```

Опечатка `hiden` иначе молча открыла бы скрытые документы.

### Подключение к роутеру приложения: `mount`

Приложению, у которого уже есть свой роутер — сайт на `tnt-framework`,
своё ядро, — раздел отдаётся участком адресов: `mount(router)` объявляет
на роутере приложения начало раздела и всё под ним, и на эти адреса
отвечает раздел своим роутером — со своими заголовками, меткой версии
и страницами отказа. Остальные адреса, слои входа и обработчик отказов
остаются у приложения.

```lua
local router = require('tnt.router')

local app = router.new()

app.get('/', function()
    return app.html('<p>главная</p>')
end)

docs.new({ directory = 'docs' }).mount(app)

app.dispatch({ method = 'GET', path = '/' }).body            --> '<p>главная</p>'
app.dispatch({ method = 'GET', path = '/docs/install' }).status   --> 200
```

В приложении на `tnt-framework` это строка в файле маршрутов: роутер
приложения приходит туда аргументом.

```lua
-- routes/web.lua
return function(route, app)
    app:get('docs').mount(route)
end
```

### Адреса раздела

| Адрес | Что отвечает |
|---|---|
| `/` | перенаправление на начало раздела — только у своего сервера |
| `/docs` | начальная страница (`start`) либо главная с карточками |
| `/docs?q=шаблоны` | страница выдачи поиска |
| `/docs/search.html?q=шаблоны` | список выдачи для окна поиска — кусок HTML |
| `/docs/search.json?q=шаблоны` | выдача поиска JSON |
| `/docs/<план>` | сводная страница плана (`plan.page`) |
| `/docs/[<свод>/]<имя>` | страница документа либо заглушка «скоро» |
| `/docs/[<свод>/]<имя>/source` | разметка документа простым текстом |
| `/docs/assets/<метка>/<файл>` | стили, сценарии, значки и шрифты раздела |

Имя страницы — латиница, цифры, дефис и подчёркивание; файл с другим
именем страницей не становится. Страница ищется среди найденных в каталоге
имён, а не чтением файла по имени из адреса: адрес `..%2F` за пределы
каталога не уведёт, потому что по адресу файл не открывается вовсе.

```lua
local site = docs.new({ directory = 'docs', hidden = { 'drafts' } })

site.dispatch({ method = 'GET', path = '/docs/install' }).status          --> 200
site.dispatch({ method = 'GET', path = '/docs/install/source' }).headers['content-type']
--> 'text/plain; charset=utf-8'
site.dispatch({ method = 'GET', path = '/docs/drafts' }).status           --> 404
site.dispatch({ method = 'GET', path = '/' }).headers.location            --> '/docs'
```

### Своды

Раздел из одного каталога — `directory`. Когда документы лежат в разных
местах — своё руководство в репозитории приложения, документы пакетов
в соседнем, — каталоги становятся **сводами**: у каждого свой участок
адреса и свои скрытые документы.

```lua
local site = docs.new({
    roots = {
        { section = 'guide', directory = 'resources/docs/guide' },
        { section = 'packages', directory = '/srv/kit/docs', hidden = { 'plan' } },
    },
})

site.dispatch({ method = 'GET', path = '/docs/guide/install' }).status      --> 200
site.dispatch({ method = 'GET', path = '/docs/packages/router' }).status    --> 200
site.dispatch({ method = 'GET', path = '/docs/packages/plan' }).status      --> 404
```

Адрес страницы в разделе — **свод и имя**: `guide/install`,
`packages/router`. Им же страница названа в меню, в группах со сводом
и в плане. Участок `assets` занят видом раздела, и свода с таким именем
не бывает.

**Ссылки между документами.** Ссылка `имя.md#якорь` — путь от каталога
документа: `views.md` — соседний документ того же свода,
`../packages/router.md` — документ соседнего свода. Ведёт она
к документу на сайте — это адрес его страницы с тем же якорем. Ведёт
к документу, которого на сайте нет (скрыт, удалён), к файлу репозитория
(`../../routes/web.lua`) или выше корня сводов — ссылка снимается
и остаётся текстом: сайт отдаёт документы, а не файлы, и ссылка в отказ
404 хуже простого текста. Внешний адрес, адрес от корня сайта и якорь
на этой же странице остаются как есть.

```lua
-- guide/install.md: «Смотрите [маршруты](../packages/router.md#шаги), [план](../packages/plan.md)
--                     и [код](../../app.lua).»

-- на странице /docs/guide/install:
--> Смотрите <a href="/docs/packages/router#шаги">маршруты</a>, план и код.
```

### Меню и группы

**Файл меню** (`menu`) — разделы и страницы по порядку чтения. Раздел
меню — заголовок второго уровня, страница — пункт списка со ссылкой
на её адрес. Уровней ровно два: читателю важно, о чём страница, а не
в каком каталоге лежит её файл.

```markdown
## Пролог

- [Обзор](/docs/guide/overview)
- [Что нового](/docs/guide/releases) {позже}
- [Что впереди](/docs/plan)

## Основы

- [Маршруты](/docs/guide/routing)
- [Генерация ссылок](/docs/guide/urls) {частично}
```

Название пункта — то, что видно в меню; заголовок страницы — из самого
документа. Фигурные скобки после ссылки — готовность **возможности**,
о которой страница: `{позже}` — её ещё нет, `{частично}` — есть
не целиком, без метки — есть. Незнакомая метка — отказ раздела (500,
причина в журнале), а не «есть»: опечатка в меню иначе молча соврала бы
о готовности. Пункт со ссылкой мимо раздела в меню не попадает. Файл
меню читается на каждой сверке: правка видна без перезапуска.

**Группы** (`groups`) — название и имена страниц по порядку; у группы
со `section` имена — внутри свода. Группы идут после разделов меню.

```lua
local site = docs.new({
    directory = 'docs',
    groups = {
        { title = 'Начало', pages = { 'install', 'usage', 'missing' } },
        { title = 'Справочник', pages = { 'usage', 'api' } },
    },
    rest = 'Ещё',
    hidden = { 'drafts' },
})

-- в каталоге: install, usage, api, changelog, drafts
-- Начало:      install, usage
-- Справочник:  api
-- Ещё:         changelog
```

Как ведёт себя то, что названо не так, как лежит на диске:

- **Пункт меню без файла** остаётся в меню заглушкой «скоро»: меню — это
  план, и у пункта есть название, которое можно показать.
- **Имя в группе без файла** — нет файла или он скрыт — пропускается:
  удалённый документ не ломает раздел, а ссылка в колонке не уводит
  в отказ.
- **Скрытый документ** не стоит нигде — ни в меню, ни в группе.
- **Страница, названная дважды,** стоит там, где названа первой: место
  у страницы одно, иначе «назад» и «вперёд» ходили бы по кругу.
- **Страница, которой нет нигде,** встаёт в последнюю группу `rest`
  по порядку адресов. Новый документ так виден на сайте сразу, а то, что
  ему не нашлось места, видно тоже — на виду, а не потерей.
- **Раздел меню и группа без страниц** не показываются.

В колонке слева раскрыт один раздел — тот, где стоит открытая страница;
у главной, выдачи и 404 — первый. «Назад» и «вперёд» под текстом идут
сквозь разделы по порядку меню, мимо заглушек.

### План ненаписанных страниц

План (`plan`) — сводная страница и то, что известно о страницах до того,
как они написаны:

```lua
local site = docs.new({
    directory = 'docs',
    menu = 'docs/menu.md',
    plan = {
        page = 'plan',
        pages = {
            releases = {
                about = 'то, что изменилось от выпуска к выпуску',
                missing = 'выпусков ещё не было',
                tasks = { '9b4cfd69' },
                note = 'первый выпуск',
            },
            install = { tasks = { '0ea5dabf' } },
        },
    },
})
```

| Поле плана страницы | Что значит |
|---|---|
| `about` | о чём будет страница — «Здесь будет рассказано про …» |
| `missing` | чего не хватает в наборе |
| `tasks` | номера задач, которыми страница закрывается |
| `note` | словами — чем закрывается |

**Заглушка.** Пункт меню без файла открывается не 404, а страницей
«Раздел скоро появится»: состояние возможности, что здесь будет, чего
не хватает и какой задачей закрывается, — из плана страницы. Первая фраза
у всех заглушек одна, и читатель узнаёт её с первого взгляда.

**Сводная страница** — `plan.page`, адрес `<начало>/<page>` — весь план
одной таблицей: раздел меню, страница с подписью «скоро», состояние
и чем закрывается, и сколько страниц написано и сколько впереди. В неё
входят пункты меню со своим планом и все, за которыми файла нет;
документы без плана — документы пакетов — не входят: «чем закрывается»
про них сказать нечего. Название сводной страницы — из меню, а меню её
не называет — «Что впереди». Документ с адресом сводной страницы
на сайте не показывается: адрес занят.

### Начало раздела

`start` — адрес, куда ведёт начало раздела: у раздела, который читают
с обзора, отдельной главной нет. Без `start` начало раздела — главная:
разделы меню с карточками страниц — заголовок и первый абзац документа,
обрезанный по слову до двухсот знаков. Поиск `?q=` на начале раздела
остаётся поиском и при `start`.

```lua
local site = docs.new({ directory = 'docs', start = '/docs/install' })

site.dispatch({ method = 'GET', path = '/docs' }).headers.location     --> '/docs/install'
```

### Карточка пакета

У страницы, которая описывает пакет, под заголовком стоит его имя
ссылкой на репозиторий, а под ним — команда установки оградой кода
с кнопкой «копировать». Какой странице какой пакет, раздел не знает:
данные даёт приложение функцией от имени страницы и её свода (у раздела
из одного каталога свода нет). Нет данных — `nil` либо `false` — нет
карточки.

```lua
local site = docs.new({
    directory = 'docs',
    card = function(name, section)
        if name == 'install' then
            return {
                name = 'app-kit',
                install = 'tt rocks install app-kit',
                repository = 'https://example.org/app-kit',
            }
        end
    end,
})
```

| Поле карточки | Что показывает |
|---|---|
| `name` | имя пакета — ссылкой на репозиторий, а без него — подписью |
| `install` | команду установки с кнопкой «копировать» |
| `repository` | адрес репозитория; без имени ссылка подписана «Репозиторий» |

Функция, вернувшая не таблицу, — ошибка программиста: страница отвечает
500, а причина уходит в журнал.

### Поиск

Указатель строится по разделам страниц — заголовок h2–h4 и текст под ним
до следующего заголовка — и по вступлению: тексту до первого заголовка,
названному заголовком страницы. Слово в указателе и в запросе сводится
к основе морфологией `tnt-morphology`, стоп-слова («и», «в», «на»)
отбрасываются.

```lua
local json = require('json')

local site = docs.new({ directory = 'docs' })
local answer = site.dispatch({ method = 'GET', path = '/docs/search.json', query = { q = 'шаги сборки' } })
local found = json.decode(answer.body)

-- docs/install.md: «## Шаги» и под ним «Сборка из каталога пакета.»
found.total               --> 1
found.partial             --> false
found.items[1].title      --> 'Установка'
found.items[1].section    --> 'Шаги'
found.items[1].url        --> '/docs/install#шаги'
found.items[1].snippet    --> '<mark>Сборка</mark> из каталога пакета.'
```

- **Все слова запроса разом.** Раздел, где стоит одно слово из двух,
  удивил бы каждого, кто набирал два. Вместе слов нет нигде — тогда
  находится хоть одно, и выдача помечена `partial`: окно и страница
  выдачи говорят об этом словами.
- **Порядок** — по оценке: число вхождений слова насыщается, короткий
  раздел весит больше длинного, а слово в заголовке раздела — заметно
  больше слова в тексте. Равные оценки идут по адресу раздела.
- **Отрывок** — целые куски текста вокруг первого совпадения, не длиннее
  180 знаков, с отметками `<mark>`; текст экранирован. Раздел, найденный
  по одному заголовку, даёт отрывком начало своего текста.
- **Пределы.** Запрос длиннее 200 знаков — отказ 400: длинный текст — это
  вставленный по ошибке абзац, а не вопрос. Окно поиска показывает
  первые 6 ответов, ответ JSON — 8, страница выдачи — 50, а число
  найденного считают все.

**Окно поиска** открывается кнопкой над меню и сочетанием ⌘K (Ctrl+K)
с любой страницы раздела. Ответы приходят по мере набора — после паузы
в наборе — кусок HTML с адреса `search.html`: тот же шаблон, что стоит
в окне при открытии, и список в окне и в ответе не расходятся вёрсткой.
Строка ответа — страница, раздел и отрывок; Enter открывает первый ответ.
Пустое окно показывает подсказки (`suggestions`): куда идти, пока ничего
не набрано.

```lua
local site = docs.new({
    directory = 'docs',
    suggestions = {
        { icon = 'book', title = 'Установка', note = 'С чего начать.', href = '/docs/install' },
    },
})
```

**Страница выдачи** — `/docs?q=…` — рисуется на узле и работает без
сценариев: это и ссылка, которой делятся, и поиск там, где окно
не откроется.

| Поле ответа JSON | Что |
|---|---|
| `query` | запрос без пробелов по краям |
| `total` | сколько разделов нашлось всего |
| `partial` | нашлись не все слова запроса |
| `items` | попадания: `title` страницы, `section` (у вступления его нет), `url` с якорем, `snippet` — HTML |

### Рамка сайта

Раздел рисует страницу целиком — с шапкой и подвалом сайта, — а адресов
сайта не знает: куда ведут марка, пункты шапки и ссылки подвала, решает
приложение настройкой `frame`.

```lua
local site = docs.new({
    directory = 'docs',
    frame = {
        brand = 'kit',
        home = '/',
        description = 'Приложение на узле Tarantool.',
        menu = {
            { title = 'Главная', href = '/' },
            { title = 'Документация', href = '/docs' },
            {
                title = 'Больше',
                columns = {
                    { { icon = 'box', title = 'Ядро', note = 'Роль узла', href = '/about#kernel' } },
                },
            },
        },
        links = {
            { title = 'Tarantool', href = 'https://www.tarantool.io/ru/doc/latest/', icon = 'book' },
            { title = 'Исходники', href = 'https://example.org/kit' },
        },
        footer = {
            note = 'Стоит на Tarantool 3: [исходники](https://example.org/kit).',
            columns = { { title = 'Разделы', links = { { title = 'Главная', href = '/' } } } },
            signature = 'узел kit-001 · среда local',
        },
    },
})
```

| Поле рамки | Умолчание | Что |
|---|---|---|
| `brand` | `title` раздела | имя сайта: шапка, подвал, заголовок вкладки |
| `home` | начало раздела | куда ведёт марка |
| `description` | нет | описание сайта: подвал и мета-теги |
| `url`, `image` | нет | внешний адрес сайта и картинка предпросмотра ссылки |
| `locale` | `ru` | язык страниц |
| `menu` | нет | пункты шапки: ссылка `{ title, href }` либо меню колонками `{ title, columns }` |
| `links` | нет | ссылки справа в шапке: `{ title, href, icon }` |
| `footer` | нет | подвал: абзац `note` разметкой, колонки ссылок, подпись внизу |

Пункт шапки отмечается открытым на своей странице и на всём под ней:
читатель на `/docs/router` стоит в разделе `/docs`. Ссылка наружу —
адрес со схемой — открывается в новой вкладке. Ссылка справа со значком
на узком экране показывается значком, без значка — уходит в меню узкого
экрана. Значки — `logo`, `menu`, `book`, `box`, `code`, `search`,
`route`, `database`, `bolt`, `terminal`, `mail`, `clock`,
`shield-check`, `arrow-right`, `angle-up`, `circle-fill`, `theme-light`,
`theme-dark`, `theme-auto`; незнакомое имя — отказ настроек. В подвале
всегда есть переключатель темы.

### Правка разметки и прогрев

Раздел помнит **издание**: страницы, навигацию и указатель, собранные
из сводов и меню. Издание сверяется с диском не чаще раза в `recheck`
секунд, и сверка идёт по самой разметке, а не по времени правки файла:
две правки в одну секунду время не различило бы.

- правка текста документа разбирает заново только его, и указатель меняет
  только его разделы;
- новый или удалённый документ разбирает заново все страницы: ссылка
  на него в других документах становится ссылкой либо перестаёт ею быть;
- файл меню разбирается на каждой сверке: он мал, а от него зависит
  только навигация;
- пока издание собирается, остальные запросы получают прежнее, а первого
  издания ждут все;
- сборка уступает цикл событий после каждого разобранного документа,
  и соседние запросы узел обслуживает и в это время.

Подключённый раздел — к серверу либо к роутеру приложения — собирает
первое издание в фоне сразу (`warm`), а не на первом запросе: разбор
сотни документов занимает секунды. Роутер, которого зовут напрямую
(`dispatch`), фоновой работы не заводит.

Документ, который не прочитать или не разобрать (разметка больше
мегабайта), в издание входит отказом: его страница отвечает 500,
остальной раздел работает, а запись «документ не собран» появляется
в журнале сразу при сборке — не дожидаясь, пока документ откроют.

### Вид

Рамка — Bootstrap 5.3 со своими токенами, шрифты Inter и Raleway. Три
колонки: меню-гармошка слева, текст на полотне посередине, оглавление
справа, которое отмечает раздел, который читают сейчас. На узком экране
боковины уходят, а их место занимают раскрывающиеся полоски: страницы
открытого раздела меню и оглавление страницы.

- **Переходы** — Turbo: страница меняется без перезагрузки, а между
  разделом и страницами сайта с другим видом — полной загрузкой.
- **Поведение** — контроллеры Stimulus: раскрытие меню, отметка раздела
  при прокрутке, окно поиска, тема, кнопка «Наверх», всплывающие
  сообщения.
- **Тема** — светлая, тёмная и «как в системе», переключателем в подвале.
  Выбор помнит `localStorage` под ключом `theme` — тем же, что у страниц
  сайта, — и тему ставит крошечный сценарий в `<head>` до первой
  отрисовки: тёмная страница не мигает светлой.
- **Подсветка кода** — Prism со своей палитрой на тёмном полотне: lua,
  bash и sh, yaml, json, sql, javascript, css и html, diff, ini и toml,
  http, nginx, make. Над оградой — подпись языка и кнопка «скопировать»;
  языка нет в наборе — ограда остаётся без раскраски.
- **Классы разметки** получают вид: `anchor` — ссылка на раздел
  по наведению, `callout-note`, `callout-warning`, `callout-tip` — врезки
  со своей подписью, `table-scroll` — широкая таблица прокручивается
  сама, а не растягивает страницу.

Без сценария раздел читается, листается и ищется страницей выдачи.

Стили, сценарии, значки и шрифты собираются из `ui/` пакета
(`bun run build`) и сразу пакуются в модуль `tnt.docs.public.bundle`;
байты — шрифты и растровые значки — лежат в нём строкой base64. Метка
версии — crc32 всего вида — стоит в адресе файла, и файл уходит
с годовым сроком жизни (`immutable`): новый выпуск пакета даёт новые
адреса, а не старые адреса с новым содержимым. Адрес с прежней меткой —
404. Текст лицензии шрифтов (OFL) лежит рядом с ними —
`assets/<метка>/fonts/OFL.txt`. Условия повторного использования
оформления — в файле NOTICE пакета.

Свои шаблоны — настройкой `views`: каталог с теми же именами, что
у пакета (`html`, `layouts/app`, `docs/layout`, `docs/show`,
`docs/upcoming`, `docs/plan`, `docs/index`, `docs/found`, `docs/refusal`,
`docs/search`, `docs/search-results`, `partials/*`).

### Отказы и заголовки

Отказ — страница на той же рамке: 404 — «Такой страницы нет» с путём
и ссылками на начало раздела и план, остальные — слово роутера и номер
происшествия, по которому запись находят в журнале узла; путь файла
и слово ядра в страницу не идут. Отказ — HTML и тогда, когда браузер
просит JSON: раздел читают глазами. Ответу JSON отказ отвечается JSON:
его читает сценарий.

Страница несёт метку версии (`etag`) и `cache-control: no-cache`:
браузер с той же страницей получает 304 без тела. `HEAD` отвечается
заголовками `GET` без тела.

Каждый ответ, отказы тоже, несёт заголовки безопасности:

| Заголовок | Значение |
|---|---|
| `content-security-policy` | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` |
| `x-content-type-options` | `nosniff` |
| `referrer-policy` | `strict-origin-when-cross-origin` |

Встроенных сценариев и стилей в разделе нет вовсе, поэтому тег
`<script>`, проскочивший бы в страницу мимо экранирования, не исполнится,
а чужой узел не встроит раздел в свою страницу.

### Роль `tnt.docs.role`

Узлу без своего приложения раздел подключается ролью со своим портом:

```yaml
roles: [tnt.docs.role]
roles_cfg:
  tnt.docs.role:
    listen: 127.0.0.1:8088
    directory: docs
    groups:
      - { title: Начало, pages: [install, usage] }
    hidden: [drafts]
    options: app.docs
```

Настройки раздела пишутся рядом с `listen` как есть. Карточку пакета —
функцию — в YAML не написать, поэтому `options` называет модуль
приложения: его таблица ложится под настройки из конфигурации, и написанное
в конфигурации главнее.

```lua
-- app/docs.lua
return {
    card = function(name)
        return { name = 'app-' .. name, install = 'tt rocks install app-' .. name }
    end,
}
```

- `listen` — порт числом (узел `127.0.0.1`) либо строка `узел:порт`.
  Раздел выходит в сеть только за обратным прокси, и умолчание узла —
  петля.
- Роли не нужен ни `box`, ни кластер: ядро зовёт её после подъёма,
  а она только читает разметку с диска.
- Повторное применение с тем же `listen` подключает новый раздел
  к прежнему серверу — порт не закрывается ни на миг; с другим `listen`
  прежний сервер закрывается, и встаёт новый.
- Проверка настроек отказывает словом без места: его читает оператор
  в alerts конфигурации.

```lua
local role = require('tnt.docs.role')

role.validate({ listen = 0, directory = 'docs' })
--> listen — порт от 1 до 65535 либо «узел:порт», а не 0
```

## Чем пришлось поступиться

- **Поиск — свой указатель в памяти, а не пакет полнотекстового поиска.**
  Свой обратный индекс `tnt-search` живёт в спейсах `box`, а его второй
  драйвер — внешняя служба; разделу документации не нужно ни то, ни
  другое. Свой драйвер к нему — это и есть оценка, отрывки и указатель,
  то есть вся работа, а фасад поверх принёс бы ряды метрик и договор
  отказа хранилища, которым в разделе нечего описывать. Поэтому указатель
  свой, на двести строк, а основа слова — та же `tnt-morphology`, что
  у `tnt-search`: запрос сводится к ключу одинаково.
- **Указатель живёт в памяти процесса** и строится заново на каждом
  подъёме: источник правды — разметка на диске, и второй экземпляр её
  слов хранить незачем. Сотня документов на 5 МБ разметки — две-три
  секунды разбора и указателя при подъёме и несколько десятков мегабайт
  памяти. Слова свода помнятся до перезапуска и копятся с правками; слова
  запроса памяти не оставляют.
- **Опечатку поиск не прощает**: «клатсер» не находит «кластер», и часть
  слова — не слово: «марш» не находит «маршруты». Допуск требует
  расстояния по словарю ключей на каждый запрос.
- **Выдача — разделы, а не страницы.** Одна страница даёт несколько
  попаданий, зато каждое ведёт к якорю, где слово и написано.
- **Отметка — кусок целиком.** Кусок — текст между пробелами и знаками
  препинания ASCII, поэтому «шаблон» в кавычках-ёлочках отмечается вместе
  с ними.
- **Ответы окна поиска и JSON — на адресах с точкой** (`search.html`,
  `search.json`), а выдача — на начале раздела, `?q=`: любое имя из одного
  участка однажды совпало бы с именем документа.
- **Относительная ссылка не на документ снимается.** Ссылка на файл
  репозитория, на `install.mdx` и на `install.md?raw=1` остаётся текстом:
  сайт таких файлов не отдаёт.
- **Документ с именем `assets`** страницу получает, а адреса исходного
  файла — нет: участок `assets/<метка>` занят видом раздела.
- **Правка видна не мгновенно**, а со следующей сверки — до `recheck`
  секунд; `recheck = 0` сверяет каталоги на каждом запросе.
- **Новый документ пересобирает все страницы**: ссылка на него в других
  документах зависит от того, есть он или нет.
- **Пределы поиска — постоянные модуля**, а не настройки: 200 знаков
  запроса, 6 ответов окна, 8 — JSON, 50 — на странице выдачи.
- **Полоса загрузки Turbo — из стилей раздела.** Свой встроенный
  `<style>` Turbo ставить не может — правило источников его не пустит, —
  и сборка вида эту вставку убирает, а правила полосы лежат в стилях
  раздела. Новый выпуск Turbo, где вставка написана иначе, сборка
  отвергает.
- **Без сценария тема светлая**, а окна поиска нет — есть страница
  выдачи; тему системы читает сценарий в `<head>`.
- **Картинки — только со своего узла** и `data:`: правило источников
  браузера не пустит картинку с чужого адреса.
- **Вид пересобирает bun.** Правка `ui/` без `bun run build` в модуль
  не попадёт; собранный модуль лежит в пакете готовым, и для установки
  bun не нужен. Модуль весит около семисот килобайт: шрифты в нём —
  base64.
- **Роль — одна на узел.** Сервер роли один на процесс; второй раздел
  на том же узле заводится вызовом `docs.new` со своим сервером. Адрес
  `listen` — IPv4 либо имя узла: IPv6 в квадратных скобках роль
  не разбирает.

## Проверки

Проверки лежат в `test/` и идут на luatest: `make check`. Каталоги
разметки у каждой проверки свои и временные; сайт проверяется запросом
и ответом без сокета, роль — настоящим сервером на свободном порту.
Каждый пример этого документа исполняется проверкой
`test/examples_test.lua`.

Покрытие строк — 100 %, убитых мутантов — 100 % (178 проверок, 832 мутанта
в пятнадцати модулях; упакованный вид и шаблоны страниц — данные
и разметка, их не мутируют).
